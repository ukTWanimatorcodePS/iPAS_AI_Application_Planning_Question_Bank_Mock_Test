## 待修：［P3］合法正規表示式被當作 LaTeX

位置：`src/content/validate.ts:124` 的 `LATEX`，其中 `\\[([]|\\[)\]]` 只檢查跳脫括號字元，不檢查內容用途。

以下是合法 Python 正規表示式說明，沒有使用 LaTeX：

```text
Python 的 r"\(abc\)" 可比對字面文字 (abc)，反斜線用來跳脫括號。
正規表示式 r"\[abc\]" 比對文字 [abc]，不是字元集合。
```

將任一說明分別放入測試題的題幹、選項及正解解析，三個位置都回報 1 個 LaTeX 錯誤；預期為 0。這是 2 種說明 × 3 個位置，共 6 個誤報。它們是獨立注入樣本，**不是目前題庫已存在的 6 道錯題**。

另用本機 CPython 實際確認：

```python
bool(re.fullmatch(r'\(abc\)', '(abc)'))  # True
bool(re.fullmatch(r'\[abc\]', '[abc]'))  # True
```

建議：為程式範例建立明確可識別的結構／範圍，先分離其字面內容再檢查數學標記，並加上上述不誤報測試；不要只靠「出現跳脫括號就一律禁止」。如果要求作者以獨立 code 欄位撰寫這些內容，也應在內容規約與報錯說明中明寫，避免封鎖正常的正規表示式選項或解析。這些字元本來就可同時用於數學與程式，單純擴充命令清單不能解決上下文問題。

證據：`docs/audit-1134022-probes.mjs`、`docs/audit-1134022-probes.log`、`docs/audit-1134022-regex.log`。
