## 1. f-string 註解可導致外部公式漏攔

位置：`src/content/codeLiterals.ts` 的 `scanReplacementField()`。它處理引號與括號，沒有處理 Python 的 `#` 行註解，因此註解中的 `}` 與引號仍被當成語法。

重現文字：

```text
f"""{x # }"""
}"""；$x^2=4$；"""end"""
```

前面的 f-string 本身是合法 Python 3.14 語法：註解延續至換行，其中 `}` 與三引號只是註解文字。已用本機 CPython `ast.parse()` 及 `eval()` 驗證，令 x=7 時輸出 `'7'`，沒有語法警告。

公式 `$x^2=4$` 明確在這段 f-string 之外。然而掃描器在註解中的 `}` 提前結束替換欄位，接著把註解內三引號誤當外層結尾；後面真正的外層結尾又被當成新開頭，吞掉公式。實際輸出為 ` \n} end"""`，題幹、選項、解析三個位置都回報 **0 個 LaTeX 錯誤**，應為 1。

這不是刻意把公式包進程式字串的既知豁免。與「289 種片段組合後把公式放在全文尾端」的測試差異，是本例公式後還有另一個正常字串，錯誤狀態才能再次配對並移除中間區域；尾端性質測試不能證明任意後綴均保留公式。

建議：辨識替換欄位內的行註解，跳過其中的括號與引號；或在遇到不支援的註解語法時保守返回，保留原文。新增案例應把外部公式放在兩段合法程式片段中間，直接斷言掃描後仍保留公式。

證據：`docs/audit-712ea19-probes.mjs` 的 `f-comment-triple-following-triple`；`docs/audit-712ea19-fstrings.log`。

## 2. 合法 f-string 的保守誤報

以下四種樣本均已以本機 CPython 3.14.10 解析及實際求值確認合法。每種放入題幹／選項／解析，各誤報 1 個 LaTeX 錯誤，共 12 次。

| 寫法 | 原因與判斷 |
|---|---|
| `rf"{x:'>10} \(ok\)"` | 單引號是合法格式填充字元；`inSpec` 遇引號直接拒絕，原文保留。此為刻意保守的支援限制 |
| `rf"\{data["key"]} \(ok\)"` | f-string 的反斜線不會跳脫替換欄位 `{`；掃描器卻先略過下一字元，未進入欄位，留下部分原文 |
| 單引號層級的 `rf"{(\n x\n)} \(ok\)"`（其中 \n 是實際換行） | Python 3.12 起替換欄位可跨行；掃描器以非三引號為由在換行返回失敗 |
| `rf"""{x # quote " and brace }` 換行後 `} \(ok\)"""` | 註解中的引號／大括號未被忽略，掃描失敗並保留原文 |

以上案例沒有在本次測試中放過外部公式。應將「不支援而保留」明寫為限制；若要支援，按實際 Python 語法補上狀態與回歸測試，而非用更寬的刪除規則消除誤報。第一項的保守策略可接受，但不能宣稱所有合法格式規格均不誤報。

對照：`!r`、`=` debug、`!r` 加格式規格、括號內 lambda、切片／字典中的冒號、寬度／精度巢狀欄位、三引號內單一及兩個引號等所測案例均正常。

## 3. 長輸入效能與深層遞迴

獨立腳本 `docs/audit-712ea19-performance.mjs` 使用每案獨立 Node 子程序，設 5 秒 timeout，避免測試無限阻塞。以下為單次本機觀測，非跨機器效能保證。

| 輸入 | 字元數 | 掃描結果 |
|---|---:|---|
| 100,000 組普通短字串 | 400,008 | 約 16ms，外部公式保留 |
| 長度 1～250 的各種反引號 run，彼此用空格隔開 | 31,632 | 約 10ms，公式保留 |
| 長度 1～500 的 run | 125,757 | 約 96ms，公式保留 |
| 長度 1～1,000 的 run | 501,507 | 約 620ms，公式保留 |
| 長度 1～1,500 的 run | 1,127,257 | 約 2,045ms，公式保留 |
| 100／1,000 層巢狀格式欄位 | 412／4,012 | 約 0／1ms，公式保留 |
| 10,000 層巢狀格式欄位 | 40,012 | **RangeError: Maximum call stack size exceeded** |

不同長度 run 沒有配對結尾，每個 run 都會重新向後搜尋，造成重複工作。巢狀欄位則使用遞迴且沒有深度上限。10,000 層並非聲稱合法 Python 程式；對無法處理的輸入，應有界地保留／回報驗證錯誤，不應使整個驗證程序拋出未處理的堆疊例外。

建議：設定明確輸入／遞迴深度限制或改用顯式堆疊；超限保留原文並給出格式驗證錯誤。反引號可預先建立 run 資訊、重用搜尋結果，避免對每個未匹配 run 重掃全文。這是作者／CI 驗證的穩健性限制，沒有證據顯示可從公開網站遠端觸發。
