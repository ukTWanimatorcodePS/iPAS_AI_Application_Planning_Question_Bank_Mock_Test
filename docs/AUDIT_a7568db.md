## 結論

指定的 `r"\(abc\)"`／`r"\[abc\]"` 在題幹、選項、解析三個位置均不再誤報；字串外的舊 LaTeX 反例與混合句亦能攔截。

**但「Python 字串先移除」尚未完整實現：普通無前綴字串、含跳脫引號的字串及三引號字串仍會誤報。** 這些不只是格式不同的虛構例子，五種測試程式均已用本機 CPython `ast.parse()` 確認為合法語法。

另外，將公式放進 Python 字串／反引號會被豁免，屬目前設計的內容檢查限制；不能把此規則當成全面語意審核或執行安全防線。

## 待修：［P3］stripCode 沒有正確辨認多種合法 Python 字串

位置：`src/content/validate.ts:126` 的 `stripCode()`。

以下五種案例，分別注入題幹、選項、正解解析，各自都回報 1 個 LaTeX 錯誤，合計 15 個誤報；預期均為 0：

```python
pattern = "\\(abc\\)"
re.findall("\\[abc\\]", s)
pattern = '\\(abc\\)'
pattern = r"a\"\(abc\)"
pattern = r"""\(abc\)"""
```

根因分兩部分：

1. `\b[rRbBuUfF]{0,2}` 即使前綴長度為零，也要求引號前的 word boundary；賦值空格、左括號與引號都是非 word 字元，普通 `"…"`／`'…'` 因而不匹配。不能只測 r/b/f/u 前綴而稱全部 Python 字串均已豁免。
2. `"[^"\n]*"`／`'[^'\n]*'` 不處理跳脫引號，也不辨識三引號，會提前結束、只移除部分內容；其餘反斜線括號仍被當作 LaTeX。

這些是針對驗證器的注入案例，**不是目前題庫有 15 道錯題**。但後續新增正規表示式及 Python 判讀題時會擋住合法內容，與本次要求的字串豁免範圍直接相關。

建議：使用小型字串／程式碼片段掃描器，明確處理無前綴、合法前綴組合、跳脫字元與三引號，再檢查未豁免的文字。若刻意只支援單行簡單字串，也應限制對外宣稱並提供明確作者寫法；普通無前綴字串至少應補回歸案例。

### 可繞過情況與實際風險判斷

下列句子回報 0 個 LaTeX 錯誤：

```text
若 r"$x^2=4$"，求 x。
若 `$x^2=4$`，求 x。
```

若這是在考 Python 字串或展示原始碼，豁免合理；若作者只是替一般數學題套上字串／反引號，公式原碼仍會出現在純文字題目 UI，屬漏檢。因此風險是 **內容品質／顯示正確性**，不是使用者任意執行程式、取得金鑰或損毀資料的安全漏洞；這個驗證器沒有執行注入字串。

不建議為攔此情況再把所有程式字串重新視為公式，否則會重現原本正規表示式誤報。應以可識別的內容結構或明確作者規約區分程式字面值與一般講解，再保留人工內容審閱。已知無法靠這個正則式完成語意判別。

未成對引號與中文引號的所測案例沒有造成新的放行；不能由有限案例推論所有任意拼接都安全。多行、巢狀／多反引號、完整 f-string 語法不應宣稱已由目前規則完整解析。
