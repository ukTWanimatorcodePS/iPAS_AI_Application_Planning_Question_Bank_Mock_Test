## 二、為什麼原本的流程沒有發現

| 環節 | 實際發生的事 | 被放過的原因 |
| --- | --- | --- |
| 官方資料蒐集 | 只讀了考試資訊「網頁」，沒有打開簡章 PDF；第一階段「未核實就填 null」的保守設定被直接沿用 | 把「網頁上沒寫」誤當成「官方沒公告」；更糟的是單元測試把 `questionCount` 必須為 null 寫成通過條件，使錯誤被測試保護 |
| 題目編寫 | 正解選項用「A、B、C 或 D」列舉多種做法（#1），其中混入一個屬於不同類別的項目 | 逐題自查時只確認「整體方向正確」，沒有逐一檢查列舉中的每個元素；列舉式選項特別容易藏錯 |
| 法規與統計用語 | 把條文的適用條件簡化成關鍵字（「自動化評分」「不偏」「四五分之四」） | 憑記憶撰寫，沒有回到條文或原始文件核對限定條件；簡化時丟掉了「系統性且廣泛」「法律效果」「樂觀偏差而非不偏」等關鍵限定 |
| 講義與題目一致 | 同一錯誤同時出現在題目與講義的多個段落（#1 在講義出現 3 次） | 先寫講義、再依講義出題，講義的錯誤會被題目「複製並強化」；結構驗證只檢查段落存在，不檢查內容 |
| 自動驗證 | `validate:content` 只檢查結構、答案一致、相似度；`verify-python` 宣稱做語法檢查卻直接略過 | 驗證器本身沒有被測試；沒有任何機制記錄「已確認的錯誤說法」防止再犯 |
| 介面 | `official-sources.json` 新增了 14 筆紀錄，但頁面沒有使用；梯次下拉選單是空殼 | 資料與頁面分開完成，E2E 沒有斷言頁面使用了這些資料 |
| 報告 | 報告數字與覆蓋範圍憑記憶撰寫（「17 段」漏記略過的 1 段、「只送題目 ID 與選項」） | 沒有從測試輸出與程式碼直接產生或核對報告內容 |
| 測試輔助 | E2E 以子字串比對選項文字 | 題目隨機抽選，只有在抽到「結構化資料／非結構化資料」這類選項時才失敗，第二階段執行時剛好沒抽到 |

## 三、新增的防範措施

1. **已知錯誤說法檢查**（`src/content/misconceptions.ts`）：收錄本次確認的錯誤與兩份官方勘誤表的更正項目，`validate:content` 對全部題目與講義檢查；明確否定或指出錯誤的說明（如「誤當成」「並非」）不會誤報。
2. **單元測試**：`tests/unit/misconceptions.test.ts` 逐字保留 13 段原始錯誤說法確認都會被抓到、7 段正確說法不會誤報，並確認目前全部內容乾淨。
3. **考試規則測試改正**：不再要求 115 年題數與時間為 null，改為核對簡章數值；2027 規則仍不得存在。
4. **E2E 新增**：歷屆試題頁依年度／梯次／科目篩選官方紀錄並連到官方頁、切換級別後篩選重設；模考顯示 115 年規格並可套用。
5. **E2E 選項比對改為「代號＋完整文字」**；隨機題目流程重複 5 次 × 2 個裝置共 20 次全數通過。
6. **程式驗證如實回報**：分開列出實際執行、僅語法檢查、略過與失敗。
