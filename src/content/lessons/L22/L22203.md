## 原理及運作流程

### 1. 批次 vs. 串流

| 方式 | 特徵 | 例子 |
| --- | --- | --- |
| 批次處理（Batch） | 累積一段時間的資料再一次處理，延遲較高 | 每晚產生營運報表 |
| 串流處理（Streaming） | 資料到達即處理，低延遲 | 即時盜刷偵測、感測器警示 |

### 2. 分散式處理概念

- **MapReduce**：Map 階段把資料轉成鍵值對並分散處理，Reduce 階段依鍵彙總結果。
- **Spark**：以記憶體運算為主，比傳統以磁碟為主的 MapReduce 快，適合反覆運算（如機器學習）。
- **水平擴展（Scale out）**：增加機器數量；**垂直擴展（Scale up）**：升級單台機器規格。

### 3. Python 基本資料結構

```python
nums = [3, 1, 4, 1, 5]
print(len(nums))          # 5
print(sorted(set(nums)))  # [1, 3, 4, 5]  set 去除重複，sorted 回傳排序後的 list
print(nums[1:3])          # [1, 4]  切片含頭不含尾
print(nums[-1])           # 5  負索引從尾端算

count = {}
for w in ["ai", "data", "ai"]:
    count[w] = count.get(w, 0) + 1
print(count)              # {'ai': 2, 'data': 1}
```

### 4. pandas 常用操作

```python
import pandas as pd

df = pd.DataFrame({
    "city": ["台北", "台中", "台北", "高雄"],
    "sales": [100, 80, 120, None],
})

df["sales"] = df["sales"].fillna(df["sales"].median())  # 以中位數填補缺失值
high = df[df["sales"] > 90]                              # 布林條件篩選
summary = df.groupby("city")["sales"].sum()              # 分組加總
print(summary.loc["台北"])                                # 220.0（含 NaN 的欄位會轉成浮點數）
```

| 操作 | 方法 |
| --- | --- |
| 查看前幾列 | `df.head()` |
| 欄位資訊與缺失 | `df.info()`、`df.isna().sum()` |
| 去除重複 | `df.drop_duplicates()` |
| 合併表格 | `pd.merge(a, b, on="id", how="left")` |
| 分組彙總 | `df.groupby("key").agg({"x": "mean"})` |
| 排序 | `df.sort_values("x", ascending=False)` |

### 5. SQL 對照

`SELECT city, SUM(sales) FROM t GROUP BY city` 等同 pandas 的 `df.groupby("city")["sales"].sum()`。

## 容易混淆的觀念比較

| 比較 | A | B | 判斷重點 |
| --- | --- | --- | --- |
| 批次 vs. 串流 | 定期、延遲高 | 即時、延遲低 | 是否需要即時回應 |
| `list` vs. `set` | 有序、可重複 | 無序、不重複 | 去重用 set |
| `inner` vs. `left` join | 只保留兩表都有的鍵 | 保留左表全部 | 列數可能不同 |
| 水平 vs. 垂直擴展 | 加機器 | 升級單機 | 分散式系統多用水平擴展 |

## 常見考試陷阱

- ❌「`nums[1:3]` 會包含索引 3 的元素」→ 切片含頭不含尾。
- ❌「`set` 會保留原本順序與重複值」→ set 不重複、不保證順序。
- ❌「left join 後列數一定不變」→ 右表若有重複鍵，列數可能增加。
- ❌「Spark 和 MapReduce 一定要用磁碟儲存中間結果」→ Spark 以記憶體運算為主。
