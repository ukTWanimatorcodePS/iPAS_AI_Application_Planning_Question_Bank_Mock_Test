## 先備概念

- **L11401**：生成式 AI 的原理、LLM、擴散模型、幻覺。

## 必考核心觀念

- 生成式 AI 依模態分：文字、影像、音訊、影片、程式碼、多模態。
- TTS 為文字轉語音；ASR 為語音轉文字。
- 選工具看：任務適配、資料安全、成本、整合、品質可靠度、授權合規。
- 部署方式：雲端 SaaS、API 串接、地端或私有部署；資料敏感時優先考慮資料不外流的方案。

## 名詞與定義

- **多模態（Multimodal）**：能同時處理多種資料型態（文字、影像、聲音）。
- **TTS（Text-to-Speech）**：文字轉語音。
- **ASR（Automatic Speech Recognition）**：語音轉文字。
- **地端部署（On-premises）**：在企業自有環境部署系統。
- **API**：讓程式呼叫模型服務的介面。

## 原理及運作流程

### 1. 依模態分類的應用

| 模態 | 能做什麼 | 常見工具類別 |
| --- | --- | --- |
| 文字 | 問答、摘要、翻譯、撰寫、改寫、分類 | 對話式 AI 助理（LLM 聊天機器人） |
| 影像 | 文生圖、圖片編輯、擴圖、風格轉換 | 文生圖／影像生成工具 |
| 音訊 | 語音合成（TTS）、語音轉文字、配樂生成 | 語音合成與轉錄工具 |
| 影片 | 文生影片、虛擬主播、剪輯輔助 | 影片生成工具 |
| 程式碼 | 程式補全、除錯、產生測試、解釋程式 | AI 程式助理 |
| 多模態 | 看圖回答、讀圖表、語音對話 | 多模態大型模型 |

### 2. 產業應用場景

- **客服**：自動回覆草稿、對話摘要、知識庫問答。
- **行銷**：文案、社群貼文、商品圖、A/B 測試素材。
- **教育**：個人化練習題、學習助教、教材摘要。
- **醫療**：病歷摘要、衛教內容（須專業人員確認）。
- **製造**：設備手冊問答、維修步驟查詢、合成瑕疵資料。
- **軟體開發**：程式碼生成、文件產生、程式審查輔助。
- **法務與行政**：合約條款比對、公文草稿、會議紀錄。

### 3. 工具選用的評估面向

| 面向 | 要問的問題 |
| --- | --- |
| 任務適配 | 這個工具擅長我的任務與語言（例如繁體中文）嗎？ |
| 資料安全 | 輸入資料會被保存或用於訓練嗎？有企業版或私有部署嗎？ |
| 成本 | 計費方式（訂閱、依 Token、依次數），規模化後成本如何？ |
| 整合 | 是否提供 API、可否串接現有系統？ |
| 品質與可靠度 | 幻覺比例、輸出穩定度、是否可附來源？ |
| 授權與合規 | 生成內容可否商用？著作權與個資規範？ |

### 4. 部署方式

- **雲端 SaaS**：開箱即用，資料會傳到服務商。
- **API 串接**：把模型能力嵌入自家系統。
- **開源模型自建／地端部署**：資料不出企業，但需硬體與維運能力。

### 5. 計費與成本控制

- API 服務常依**輸入與輸出的 Token 數**計費：精簡提示、限制輸出長度、依任務選擇合適規模的模型，都能控制成本。
- 自建開源模型雖可提高資料控制與客製彈性，但需負擔 GPU 硬體、更新、安全修補與維運人力，且開源模型仍有授權條款需遵守。

### 6. 官方評鑑範圍點名的常見工具

官方評鑑範圍（115.06）在本細項列出下列工具。考試重點是知道各工具的**定位與適用情境**，不是操作細節（功能與方案經常更新，實際以各官方說明為準）：

| 工具 | 定位 | 典型用途 |
| --- | --- | --- |
| ChatGPT | OpenAI 的對話式生成式 AI 服務 | 文字撰寫、摘要、問答、資料整理 |
| OpenAI API | 讓開發者以程式呼叫 OpenAI 模型的介面，通常依 Token 用量計費 | 把生成式 AI 整合進自家系統或流程 |
| Gemini | Google 的生成式 AI 模型與助理 | 文字與多模態問答、與 Google 服務整合 |
| Midjourney | 文字生成影像的服務 | 概念圖、行銷素材、視覺風格探索 |
| Copilot Studio | Microsoft 的低程式碼平台，用來建立自訂的 Copilot 與 AI 代理 | 企業內部問答助理、串接內部資料與流程 |
| GitHub Copilot（含在 VS Code 中使用） | 程式碼輔助工具，可在 VS Code 等編輯器中提供補全與對話 | 撰寫、解釋、重構程式碼與測試 |
| Cursor | 內建 AI 功能的程式碼編輯器 | 以自然語言修改程式碼、跨檔案理解專案 |

- 選擇時仍回到上一節的評估面向：任務適配、資料安全（輸入的資料會不會被保存或用於訓練）、成本、整合、品質與授權。
- 程式碼輔助工具產生的程式碼仍需人工審查與測試，並注意授權與資安。

## 不同領域的實際案例

- **旅行社**：用 LLM 依客戶偏好產生行程草案，再由專員確認價格與可訂性。
- **出版社**：用語音合成製作有聲書試聽版，正式版仍由配音員錄製。
- **工廠**：把設備手冊建成問答機器人，技師以語音提問、多模態模型看照片判斷零件型號。

## 容易混淆的觀念比較

| 比較 | A | B | 判斷重點 |
| --- | --- | --- | --- |
| TTS vs. ASR | 文字 → 語音 | 語音 → 文字 | 轉換方向 |
| SaaS vs. 地端部署 | 快速、資料傳出 | 資料不出企業、維運成本高 | 資料敏感度 |
| 文生圖 vs. 影像辨識 | 生成式 | 鑑別式 | 產出內容或判斷 |
| 多模態 vs. 單一模態 | 處理多種輸入 | 只處理一種 | 看輸入輸出型態 |

## 常見考試陷阱

- ❌「所有生成式工具都可以放心輸入機密資料」→ 需確認資料使用政策。
- ❌「生成的圖片一定可以商用」→ 需確認工具授權條款與著作權風險。
- ❌「語音轉文字是生成式 AI 的唯一音訊應用」→ 還有語音合成、音樂生成等。
