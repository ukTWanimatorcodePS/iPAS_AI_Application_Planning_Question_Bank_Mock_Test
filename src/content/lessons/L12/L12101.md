## 學習目標

- 說明 No Code 與 Low Code 的定義與差異。
- 認識常見平台類型：表單與資料庫、流程自動化、網站與 App 建置、AI 模型建置（AutoML）。
- 理解公民開發者（Citizen Developer）的角色，以及 No Code / Low Code 與生成式 AI 的結合。

## 先備概念

- **工作流程（Workflow）**：完成一件工作的一連串步驟。
- **API**：讓不同系統交換資料的介面。

## 必考核心觀念

- No Code 完全不寫程式；Low Code 以視覺化為主、可寫少量程式擴充。
- 平台類型：表單資料庫、流程自動化、網站與 App 建置、AutoML、RPA。
- 流程自動化的核心是「觸發 → 條件 → 動作」。
- RPA 模擬人工畫面操作，多為規則式，適合沒有 API 的舊系統。
- 公民開發者能加快開發，但需要 IT 治理。

## 名詞與定義

- **No Code**：不需撰寫程式即可建置應用。
- **Low Code**：以視覺化為主、可搭配少量程式的開發方式。
- **公民開發者（Citizen Developer）**：使用低／無程式工具開發的非專業開發者。
- **RPA（Robotic Process Automation）**：以軟體機器人模擬人類電腦操作。
- **AutoML**：自動化完成特徵處理、模型選擇與調參的機器學習工具。

## 原理及運作流程

### 1. 定義

- **No Code（無程式碼）**：透過圖形化介面、拖拉元件、設定選項完成應用，**完全不需撰寫程式**，主要給業務人員使用。
- **Low Code（低程式碼）**：以視覺化開發為主，但**允許在需要時撰寫少量程式**擴充功能，適合具基礎技術能力的人員或 IT 團隊加速開發。

可以把兩者想成光譜：傳統開發（全部寫程式）← Low Code → No Code（不寫程式）。

### 2. 常見平台類型

| 類型 | 做什麼 | 典型功能 |
| --- | --- | --- |
| 表單／資料庫 | 蒐集與管理資料 | 線上表單、表格式資料庫、權限 |
| 流程自動化 | 串接多個服務自動執行 | 觸發條件 → 動作，例如收到表單就寄信並寫入試算表 |
| 網站／App 建置 | 拖拉做出介面 | 範本、元件、發布 |
| AutoML／AI 建置 | 不寫程式訓練模型 | 上傳資料、自動選模型與調參、部署 API |
| RPA | 模擬人在電腦上的重複操作 | 自動點選、複製貼上、登入系統 |

### 3. 運作核心：觸發與動作

流程自動化平台多採「**觸發（Trigger）→ 條件 → 動作（Action）**」模式。例如：「當 Email 收到含附件的報價單（觸發）→ 若金額大於 10 萬（條件）→ 通知主管並建立簽核單（動作）」。

### 4. 與生成式 AI 結合

- 在流程中加入 LLM 步驟：自動摘要信件、分類客訴、翻譯。
- 用自然語言描述需求，讓平台產生表單、流程或公式。
- 以拖拉方式建立 AI 聊天機器人並串接企業知識庫。

### 5. 公民開發者

指非 IT 部門、但能使用 No Code / Low Code 工具開發應用的業務人員。好處是貼近需求、開發快；但需 IT 提供平台治理，避免資料外洩與「影子 IT」。

## 不同領域的實際案例

- **人資**：用表單平台建立請假申請，送出後自動通知主管並記錄到試算表。
- **零售**：店長以 AutoML 上傳過去銷售資料，建立需求預測模型。
- **財務**：用 RPA 每天自動登入銀行網站下載對帳單。

## 容易混淆的觀念比較

| 比較 | A | B | 判斷重點 |
| --- | --- | --- | --- |
| No Code vs. Low Code | 完全不寫程式 | 可寫少量程式擴充 | 是否允許程式碼 |
| RPA vs. API 串接 | 模擬畫面操作 | 系統間直接交換資料 | API 較穩定，RPA 適合無 API 的舊系統 |
| AutoML vs. 傳統建模 | 自動選模型與調參 | 資料科學家手動設計 | 自動化程度 |
| 公民開發者 vs. 專業開發者 | 業務人員 | IT／工程師 | 背景與工具 |

## 常見考試陷阱

- ❌「No Code 和 Low Code 完全一樣」→ Low Code 允許撰寫程式。
- ❌「用了 No Code 就不需要 IT 部門」→ 仍需治理、資安與整合支援。
- ❌「RPA 就是 AI」→ RPA 多為規則式自動化，可搭配 AI 但本身不一定有學習能力。

## 單元重點整理

1. No Code 不寫程式、Low Code 可寫少量程式。
2. 平台類型：表單資料庫、流程自動化、網站 App、AutoML、RPA。
3. 自動化核心：觸發 → 條件 → 動作。
4. 公民開發者提升速度，但需 IT 治理。
